## 1. 一句话用法

在 Controller 方法上加一行注解即可，其余全部由中间件完成：

```java
@RestController
@RequestMapping("/api/v1/simulations")
public class InboundSimulationController {

    private final InboundSimulationService service;

    public InboundSimulationController(InboundSimulationService service) {
        this.service = service;
    }

    /** 执行入库仿真（API-055）。 */
    @PostMapping("/inbound")
    @PreAuthorize("hasAuthority('sim:run')")     // ← 只需这一行
    public ApiResponse<InboundSimulationVO> run(@RequestBody @Valid InboundRequest request) {
        return ApiResponse.ok(service.run(request));
    }
}
```

需要「登录即可、不校验具体权限」的接口（如 API-002 登出、API-003 当前用户），**不加注解**：

```java
@PostMapping("/logout")
public ApiResponse<Void> logout() { ... }        // 已登录即可访问，无需 @PreAuthorize
```

## 2. 鉴权链路

```
客户端请求
   │  Authorization: Bearer <token>
   ▼
JwtAuthFilter ──解析并验签──► 写入 SecurityContext（LoginUser + 权限码）
   │  Token 缺失/非法/过期：不抛异常，放行到下一环
   ▼
Spring Security 过滤器链 ──未认证──► RestAuthenticationEntryPoint ──► 401 + 40101
   │  （仅 /api/v1/auth/login 免认证）
   ▼
@PreAuthorize("hasAuthority('权限码')") ──无权限──► RestAccessDeniedHandler ──► 403 + 40301
   │  有权限
   ▼
Controller 业务方法
```

要点：

1. **白名单只有一个**：`POST /api/v1/auth/login`（API-001）。其余接口（含 b、c 的全部接口）一律需要登录。
2. **无状态**：不创建 Session；请求头 `Authorization` 是唯一凭证。
3. **Token 中已包含权限码**，因此每次请求不查库即可完成鉴权（性能友好，NFR-1）。
4. **权限变更后旧 Token 仍带旧权限**：管理员改完角色权限（API-014）后，被影响用户需重新登录才生效。
5. **鉴权先于参数校验**（见下文 2.1），越权请求一律 403，不会先漏出 400 的参数结构。

### 2.1 执行顺序：鉴权必须先于参数校验（重要）

`@PreAuthorize` 的执行时机在 `@Valid` **之后**。这意味着只写方法级注解时，越权者带一个非法请求体调用接口，
会先拿到 `400 参数校验失败`（暴露参数结构），而不是 `403 无该操作权限`——不满足 FR-RBAC-5。

因此 a 已在 `SecurityConfig` 的过滤器链上按《接口文档》1.4 **逐接口声明权限**（过滤器链在进入 MVC 之前生效）：

| 路径 | 权限码 |
| --- | --- |
| `POST /api/v1/auth/login` | 公开（唯一白名单） |
| `/api/v1/auth/**`（其余） | 登录即可 |
| `/api/v1/users/**`、`/api/v1/roles/**`、`/api/v1/permissions/**` | `user:manage` |
| `GET /api/v1/warehouses/**`、`GET /api/v1/racks/**`、`GET /api/v1/locations/**` | `sim:view` |
| 其余 `/api/v1/warehouses/**`、`/api/v1/racks/**`、`/api/v1/locations/**` | `warehouse:manage` |
| `GET /api/v1/skus/**`、`GET /api/v1/orders/**` | `sim:view` |
| 其余 `/api/v1/skus/**`、`/api/v1/orders/**` | `sku:manage` |
| `POST /api/v1/orders/generate` | `sim:run`（必须排在 orders 通配之前） |
| `/api/v1/import/**` | `sku:manage` |
| `/api/v1/export/**` | `sim:view` |
| `/api/v1/recommendations/**` | `recommend:view` |
| `/api/v1/config/**` | `config:manage` |
| `/api/v1/plans/**` | `compare:view` |
| `GET /api/v1/plans/*/export` | `report:export`（须排在 plans 通配之前） |
| `GET /api/v1/strategies`、`GET /api/v1/simulations/**` | `sim:view` |
| 其余 `/api/v1/strategies`、`/api/v1/simulations/**` | `sim:run` |
| 其他（如 `/api/v1/health`） | 登录即可 |

> **给 b、c 的结论**：`@PreAuthorize` 仍要写（纵深防御第二道防线，且是 Code Review 的检查项），
> 但**真正拦住「带非法参数的越权请求」的是上表的 URL 规则**。
> **新增接口时**：先更新《接口文档》与上表（找 a 改 `SecurityConfig`），再写代码；
> 否则新接口会落到「登录即可」兜底规则上，形成**裸奔接口**（Code Review 清单第 3 项）。

```java
@RestController
@RequestMapping("/api/v1/simulations")
@PreAuthorize("hasAuthority('sim:run')")     // 类级：本类全部接口统一要求该权限
public class InboundSimulationController { ... }
```

## 3. Token 契约

### 3.1 请求头

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

- 前缀 `Bearer ` 不可省略，多一个空格都会导致 401。
- Token 由 API-001 登录接口签发，默认有效期 **8 小时**（`wms.security.token-expire-seconds`）。

### 3.2 载荷（JWT Claims）

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `sub` | String | 登录账号，如 `admin` |
| `uid` | Long | 用户 id |
| `name` | String | 姓名/昵称 |
| `roles` | List&lt;String&gt; | 角色标识，如 `["admin"]` |
| `perms` | List&lt;String&gt; | **权限码列表**，如 `["user:manage","sim:run"]` |
| `iat` / `exp` | Number | 签发时间 / 过期时间（秒级时间戳） |

> 签名算法固定 **HS256**，密钥由 `wms.security.jwt-secret` 配置，长度不足 32 字节时应用**拒绝启动**（避免弱密钥）。

### 3.3 取当前登录用户

```java
@GetMapping("/me")
public ApiResponse<UserVO> me(@AuthenticationPrincipal LoginUser loginUser) {
    Long userId = loginUser.getUserId();
    String account = loginUser.getAccount();
    Set<String> permissions = loginUser.getPermissions();
    // 注意：loginUser 永不含密码（getPassword() 恒为 null）
    ...
}
```

`LoginUser` 字段：

| 方法 | 类型 | 说明 |
| --- | --- | --- |
| `getUserId()` | Long | 用户 id |
| `getAccount()` | String | 登录账号 |
| `getName()` | String | 姓名/昵称 |
| `getRoles()` | Set&lt;String&gt; | 角色标识 |
| `getPermissions()` | Set&lt;String&gt; | 权限码集合 |
| `hasPermission(String)` | boolean | **仅供展示性判断**，不得作为接口安全边界 |

> ⚠ **禁止**用 `loginUser.hasPermission(...)` 替代 `@PreAuthorize` 做接口鉴权。
> 后端强制鉴权是唯一安全边界（FR-RBAC-3）；`if (hasPermission) { ... }` 这类写法一旦漏写分支就会越权。

## 5. 返回格式（冻结）

### 5.1 未认证 / Token 失效 → 401

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json;charset=UTF-8

{ "code": 40101, "message": "未登录或登录已失效，请重新登录", "data": null }
```

- **不会**返回 `WWW-Authenticate: Basic` 挑战头，**不会** 302 重定向到登录页；
- 前端 axios 拦截器据此跳转登录页（《代码规范》5.4）。

### 5.2 已登录但越权 → 403（FR-RBAC-5）

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json;charset=UTF-8

{ "code": 40301, "message": "无该操作权限", "data": null }
```

### 5.3 其他错误码

| 错误码 | HTTP | 触发 |
| --- | --- | --- |
| 40102 | 401 | 登录时账号或密码错误 |
| 40103 | 401 | 账号已被禁用 |
| 40001 | 400 | 参数校验失败 |
| 404xx | 404 | 资源不存在（如 40404 库位不存在、40412 请求的接口不存在） |
| 422xx | 422 | 业务规则失败（如 42201 库位已占用） |

> 完整清单见 `com.wms.common.ErrorCode`。**b、c 的业务异常统一抛 `BizException`**，
> 由全局异常处理器转换为上述结构，禁止自行拼装响应体：

```java
throw new BizException(ErrorCode.PLAN_NOT_FOUND);
throw new BizException(ErrorCode.WEIGHT_LAYER_VIOLATION, "库位 A-01-03-02 层高 3 超过重货阈值 2");
```

## 6. 前端配合约定

前端只做**显隐**，不做安全边界（《代码规范》4.3、5.3）：

1. 路由 `meta.permission` 声明所需权限，全局守卫校验；
2. 按钮/菜单按 `authStore.hasPermission('权限码')` 显隐；
3. 仍必须处理后端 401/403：401 跳登录、403 提示「无该操作权限」。

```ts
// src/router/index.ts
{ path: '/simulation/config', component: SimConfig, meta: { permission: 'sim:run' } }

// src/api/http.ts（统一拦截）
http.interceptors.response.use(
  (r) => r.data,
  (err) => {
    if (err.response?.status === 401) authStore.logout()          // 40101
    else if (err.response?.status === 403) toast('无该操作权限')    // 40301
    return Promise.reject(err)
  }
)
```

## 7. 常见错误自查（Code Review 清单）

| 症状 | 原因 |
| --- | --- |
| 接口返回 401 但已带 Token | `Bearer ` 前缀缺失/多余空格；Token 过期；服务端 `jwt-secret` 被改过 |
| 接口返回 403 但该角色「应该有权限」 | 权限码拼写不符（如写成 `sim:run:inbound`）；或改完权限后未重新登录 |
| 前端拿不到数据但 curl 正常 | 浏览器未带 `Authorization`；跨域预检被拦（`wms.cors.allowed-origins` 未包含前端地址） |
| 接口「裸奔」可匿名访问 | 该接口未加 `@PreAuthorize`，且不在白名单——**这是最高优先级缺陷** |
| 启动报 `jwt-secret 长度不足 32 字节` | 密钥太短，HS256 要求 ≥ 32 字节 |

## 8. 验收步骤（本中间件的验收证据）

```bash
# 1. 未带 Token → 期望 401 且 code=40101
curl -i http://127.0.0.1:8081/api/v1/warehouses

# 2. 登录拿 Token（API-001，第 4 步交付）
TOKEN=$(curl -s -X POST http://127.0.0.1:8081/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"account":"operator","password":"admin123"}' | jq -r .data.token)

# 3. 带 Token 访问有权限的接口 → 期望 200
curl -i -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8081/api/v1/skus

# 4. operator 访问仅 admin 可用的接口 → 期望 403 且 code=40301
curl -i -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8081/api/v1/users

# 5. 伪造 Token（换密钥签名）→ 期望 401
curl -i -H "Authorization: Bearer forged.token.value" http://127.0.0.1:8081/api/v1/skus
```
