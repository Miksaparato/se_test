## 1. 环境准备

| 依赖 | 版本要求 | 检查命令 |
| --- | --- | --- |
| JDK | **17 或以上**（Spring Boot 3.2 硬性要求） | `java -version` 显示 17+ |
| Maven | 3.6+ | `mvn -v`（其 Java 版本也须为 17+） |
| MySQL | 8.0+ | `mysql --version` |
| Node.js | 18+ | `node --version` |

> ⚠ 若 `java -version` 是 17 而 `mvn -v` 仍显示 1.8，说明 `JAVA_HOME` 未指向 JDK 17。

## 2. 启动步骤

### 2.1 准备数据库

```sql
CREATE DATABASE wms_sim DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

表结构与种子数据**无需手工执行**：应用启动时 Flyway 自动执行 `V1~V3` 脚本。

### 2.2 启动后端

```bash
cd backend
mvn -s maven-settings.xml spring-boot:run
```

- 默认端口 `8080`；数据库连接可用环境变量覆盖：`WMS_DB_URL` / `WMS_DB_USERNAME` / `WMS_DB_PASSWORD`
- 生产环境必须覆盖 `WMS_JWT_SECRET`（HS256 要求 ≥ 32 字节，过短应用会拒绝启动）
- `-s maven-settings.xml` 是必须的：本机全局 Maven 配置的本地仓库路径不存在、镜像不可达，
  该文件把本地仓库固定到工程内 `.mvn-repo/`、镜像改为 Maven Central

启动成功标志：控制台出现 `Started WmsApplication` 且 Flyway 输出 3 条 `Successfully applied`。

### 2.3 启动前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173，/api 自动代理到 8080
```

### 2.4 自检

```bash
curl -i http://127.0.0.1:8080/api/v1/health
# 期望：HTTP 401 + {"code":40101,...}（未登录被鉴权中间件拦截，说明安全边界生效）
```

## 4. 功能操作说明（a 负责模块）

### 4.1 登录与权限（界面需求 8.1、8.6）

1. 打开前端地址，输入账号密码登录（API-001）。登录页提供四个演示账号的一键填充按钮。
2. 登录后**菜单按角色自动过滤**：`viewer`/`operator` 看不到「系统管理」分组。
3. 越权时页面跳转 403 页并提示「无访问权限」；接口层同时返回 `403 + 40301`——
   **前端显隐只是体验优化，后端强制鉴权才是安全边界**。
4. 「角色与权限」页（仅 admin）：可新建角色、为角色勾选 9 个权限码（全量覆盖语义）、删除自定义角色。
   - 内置四角色**不可删除**，但权限可调整（FR-RBAC-4）
   - 仍被用户引用的角色不可删除（提示「该角色仍被 N 个用户使用」）
5. 「用户管理」页（仅 admin）：新建用户并指定角色、启用/禁用、删除。
   - 禁用后的账号**无法登录**（提示「账号已被禁用」）
   - 不允许禁用/删除**当前登录账号**；保留账号 `admin` 不允许删除
6. **权限变更的生效时机**：管理员调整角色权限后，被影响的用户需**重新登录**才生效
   （Token 携带权限，无状态 JWT 的既有取舍，详见《鉴权中间件规范》2.4）。

### 4.2 仓库建模（FR-1.1、API-016~021）

1. 「仓库管理」→ 新建仓库：填编码（唯一，如 `WH-01`）、名称、长宽高、**出库口坐标**。
   - 出库口坐标是距离计算的终点（曼哈顿距离 `|x1-x2|+|y1-y2|`），影响推荐与仿真结果，务必填写真实位置
   - 编码创建后不可修改（库位编码与平面图数据以其为引用基础）
2. 「货架管理」→ 选择仓库 → 新建货架：填编码（如 `A-01`）、巷道、列数、层数、基准坐标、排布方向，
   勾选「**批量生成库位**」可一次性按 列×层 生成库位（如 3 列 × 2 层 = 6 个）。
   - 库位编码自动生成为 `巷道-货架序号-列-层`，例如 `A-01-03-02`
   - 排布方向：`沿 x 递增` 时同一列的库位 x 随列号增大；`沿 y 递增` 时 y 随列号增大
3. 「库位管理」：可按仓库/货架/状态过滤；手工新增时注意：
   - 编码全局唯一
   - **层号不得超过所属货架的层数上限**
   - 状态选「占用」时必须填写占用货物 id（一库位一货物约束）
4. 「仓库总览」：查看所选仓库的布局概况（货架数、库位总数、空闲/占用/停用统计）。
   平面图可视化由 c 的公共组件渲染，接入后本页直接展示图形化布局。

> **删除保护**：仓库下有货架、货架下有库位、库位处于占用状态时，均不允许删除（返回 42210）。

### 4.3 货物与订单（FR-1.2、FR-1.3、API-029~040）

**货物（SKU）**——三个字段是推荐与仿真的核心输入，录入质量直接决定推荐效果：

| 字段 | 含义 | 对算法的影响 |
| --- | --- | --- |
| 重量 | kg | 越重越倾向低层（默认权重 30%） |
| 周转频次 | 次/单位时间 | 越高越靠出库口（默认权重 40%） |
| 出库优先级 | 1~5 | 越高越靠出库口（默认权重 20%） |

尺寸三项（长宽高）要么都填、要么都不填；填写后用于与库位容量（体积）做校验。

**订单**：录货物、数量、优先级、下达时间。列表默认按「**优先级降序 + 下达时间升序**」排列，
这与出库仿真的拣选顺序一致。订单状态：待出库 → 拣选中 → 已完成 / 已取消；
仅「待出库」「已取消」可删除；已完成订单不允许修改货物与数量。

**批量导入（API-037/038）**：支持 CSV 与 Excel（.xlsx/.xls）。

SKU 表头：

```
skuCode,name,weight,turnoverRate,priority,category,length,width,height,remark
SKU-001,高频电子元件,50,0.9,5,电子,30,20,10,
```

订单表头（用 `skuCode` 指定货物）：

```
orderNo,skuCode,quantity,priority,placedAt,status,remark
SO-20260910-001,SKU-001,20,4,2026-09-10T09:00:00,pending,
```

导入要点：

1. 列顺序可变，按**列名**匹配；Excel 另存为的带 BOM 的 CSV 也能正常识别
2. 合法行入库，非法行**不会导致整体失败**，页面逐行显示「行号 + 列 + 原因」，据此修改后重传
3. 重复编码/订单号策略：`跳过`（默认，不覆盖已有数据）或 `覆盖更新`
4. `placedAt` 支持 `yyyy-MM-dd`、`yyyy-MM-dd HH:mm[:ss]`、`yyyy-MM-ddTHH:mm[:ss]`，留空取当前时间

**导出（API-039/040）**：CSV 或 JSON。
CSV 带 UTF-8 BOM 与 CRLF 行尾，**用 Excel 直接打开中文不乱码**；
导出文件可原样作为导入模板使用。

## 5. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `无效的标记: --release` | Maven 使用的 JDK 不是 17+，检查 `JAVA_HOME` 与 `mvn -v` |
| 启动报 `jwt-secret 长度不足 32 字节` | `WMS_JWT_SECRET` 太短，HS256 要求 ≥ 32 字节 |
| 启动报 `.part.lock (系统找不到指定的路径)` | 未加 `-s maven-settings.xml`，Maven 用了全局配置里不存在的本地仓库 |
| 所有接口都返回 401 | 未登录或 Token 过期（默认 8 小时）；重新登录即可 |
| 明明有权限却返回 403 | 权限码拼写不符；或管理员刚改过权限，**需重新登录**才生效 |
| 页面菜单少了功能 | 当前角色确实没有该权限（可对照《鉴权中间件规范》第 4 节权限矩阵） |
| 导出 CSV 用 Excel 打开中文乱码 | 使用系统的导出功能（已带 BOM）；不要用浏览器另存或第三方转换 |
| 建库位提示「层号超出货架层数上限」 | 货架层数不足，先改货架层数或降低层号 |
| 删仓库/货架提示「资源被引用」 | 需先删除下级数据（货架/库位），占用状态的库位需先释放货物 |
| 前端 `npm run dev` 起不来 | Node 版本需 ≥ 18；先 `npm install` |
