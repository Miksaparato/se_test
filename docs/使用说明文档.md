## 2. 启动步骤

### 2.1 准备数据库

```sql
CREATE DATABASE wms_sim DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

表结构与种子数据**无需手工执行**：应用启动时 Flyway 自动执行 `V1~V3` 脚本。

> **若数据库是按 `backend/sql/schema.sql` 手工建的**（方式二）：库里没有 `flyway_schema_history`，
> Flyway 会以 `baseline-version`（默认 3）**认领既有结构**并跳过 `V1~V3`，
> 不会因「表已存在」报错、也不会改动任何数据；此后从 `V4` 继续版本化。
> 需要更严格的校验时用 `WMS_FLYWAY_BASELINE_VERSION=0` 覆盖。
>
> **无 MySQL 也能跑**：加 `--wms.repository=memory`（或设环境变量 `WMS_REPOSITORY=memory`）
> 可启用内置演示数据（1 仓库 / 3 货架 / 36 库位 / 5 货物 / 3 方案）离线启动。

### 2.2 启动后端

```bash
cd backend
mvn -s maven-settings.xml spring-boot:run
```

- 默认端口 `8080`；数据库连接可用环境变量覆盖：`WMS_DB_URL` / `WMS_DB_USERNAME` / `WMS_DB_PASSWORD`
- 生产环境必须覆盖 `WMS_JWT_SECRET`（HS256 要求 ≥ 32 字节，过短应用会拒绝启动）
- `-s maven-settings.xml` 是必须的：本机全局 Maven 配置的本地仓库路径不存在、镜像不可达，
  该文件把本地仓库固定到工程内 `.mvn-repo/`、镜像改为 Maven Central

启动成功标志：控制台出现 `Started WmsApplication` 且 Flyway 输出 3 条 `Successfully applied`。

### 2.3 启动前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173，/api 自动代理到 8080
```

### 2.4 自检

```bash
curl -i http://127.0.0.1:8080/api/v1/health
# 期望：HTTP 401 + {"code":40101,...}（未登录被鉴权中间件拦截，说明安全边界生效）
```

## 4. 功能操作说明（a 负责模块）

### 4.1 登录与权限（界面需求 8.1、8.6）

1. 打开前端地址，输入账号密码登录（API-001）。登录页提供四个演示账号的一键填充按钮。
2. 登录后**菜单按角色自动过滤**：`viewer`/`operator` 看不到「系统管理」分组。
3. 越权时页面跳转 403 页并提示「无访问权限」；接口层同时返回 `403 + 40301`——
   **前端显隐只是体验优化，后端强制鉴权才是安全边界**。
4. 「角色与权限」页（仅 admin）：可新建角色、为角色勾选 9 个权限码（全量覆盖语义）、删除自定义角色。
   - 内置四角色**不可删除**，但权限可调整（FR-RBAC-4）
   - 仍被用户引用的角色不可删除（提示「该角色仍被 N 个用户使用」）
5. 「用户管理」页（仅 admin）：新建用户并指定角色、启用/禁用、删除。
   - 禁用后的账号**无法登录**（提示「账号已被禁用」）
   - 不允许禁用/删除**当前登录账号**；保留账号 `admin` 不允许删除
6. **权限变更的生效时机**：管理员调整角色权限后，被影响的用户需**重新登录**才生效
   （Token 携带权限，无状态 JWT 的既有取舍，详见《鉴权中间件规范》2.4）。

### 4.2 仓库建模（FR-1.1、API-016~021）

1. 「仓库管理」→ 新建仓库：填编码（唯一，如 `WH-01`）、名称、长宽高、**出库口坐标**。
   - 出库口坐标是距离计算的终点（曼哈顿距离 `|x1-x2|+|y1-y2|`），影响推荐与仿真结果，务必填写真实位置
   - 编码创建后不可修改（库位编码与平面图数据以其为引用基础）
2. 「货架管理」→ 选择仓库 → 新建货架：填编码（如 `A-01`）、巷道、列数、层数、基准坐标、排布方向，
   勾选「**批量生成库位**」可一次性按 列×层 生成库位（如 3 列 × 2 层 = 6 个）。
   - 库位编码自动生成为 `巷道-货架序号-列-层`，例如 `A-01-03-02`
   - 排布方向：`沿 x 递增` 时同一列的库位 x 随列号增大；`沿 y 递增` 时 y 随列号增大
   - **库位容量**：与货物尺寸同为体积口径，单位必须一致；留空取默认值 `100.000`。
     若货物尺寸按厘米录入（如 `30×20×10 = 6000`），必须显式填更大的容量（如 `100000`），
     否则容量校验会把所有库位判为「放不下」，推荐与入库仿真都会报「无可用库位」
3. 「库位管理」：可按仓库/货架/状态过滤；手工新增时注意：
   - 编码全局唯一
   - **层号不得超过所属货架的层数上限**
   - 状态选「占用」时必须填写占用货物 id（一库位一货物约束）
4. 「仓库总览」：查看所选仓库的布局概况（货架数、库位总数、空闲/占用/停用统计），
   并可**按层切换平面图**、点击库位查看编码/坐标/层号/容量/距出库口距离。
   平面图由 c 的 C-F1 公共组件渲染（详见附录 C-3）。

> **删除保护**：仓库下有货架、货架下有库位、库位处于占用状态时，均不允许删除（返回 42210）。

### 4.3 货物与订单（FR-1.2、FR-1.3、API-029~040）

**货物（SKU）**——三个字段是推荐与仿真的核心输入，录入质量直接决定推荐效果：

| 字段 | 含义 | 对算法的影响 |
| --- | --- | --- |
| 重量 | kg | 越重越倾向低层（默认权重 30%） |
| 周转频次 | 次/单位时间 | 越高越靠出库口（默认权重 40%） |
| 出库优先级 | 1~5 | 越高越靠出库口（默认权重 20%） |

尺寸三项（长宽高）要么都填、要么都不填；填写后用于与库位容量（体积）做校验。

**订单**：录货物、数量、优先级、下达时间。列表默认按「**优先级降序 + 下达时间升序**」排列，
这与出库仿真的拣选顺序一致。订单状态：待出库 → 拣选中 → 已完成 / 已取消；
仅「待出库」「已取消」可删除；已完成订单不允许修改货物与数量。

**批量导入（API-037/038）**：支持 CSV 与 Excel（.xlsx/.xls）。

SKU 表头：

```
skuCode,name,weight,turnoverRate,priority,category,length,width,height,remark
SKU-001,高频电子元件,50,0.9,5,电子,30,20,10,
```

订单表头（用 `skuCode` 指定货物）：

```
orderNo,skuCode,quantity,priority,placedAt,status,remark
SO-20260910-001,SKU-001,20,4,2026-09-10T09:00:00,pending,
```

导入要点：

1. 列顺序可变，按**列名**匹配；Excel 另存为的带 BOM 的 CSV 也能正常识别
2. 合法行入库，非法行**不会导致整体失败**，页面逐行显示「行号 + 列 + 原因」，据此修改后重传
3. 重复编码/订单号策略：`跳过`（默认，不覆盖已有数据）或 `覆盖更新`
4. `placedAt` 支持 `yyyy-MM-dd`、`yyyy-MM-dd HH:mm[:ss]`、`yyyy-MM-ddTHH:mm[:ss]`，留空取当前时间

**导出（API-039/040）**：CSV 或 JSON。
CSV 带 UTF-8 BOM 与 CRLF 行尾，**用 Excel 直接打开中文不乱码**；
导出文件可原样作为导入模板使用。

## 5. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `无效的标记: --release` | Maven 使用的 JDK 不是 17+，检查 `JAVA_HOME` 与 `mvn -v` |
| 启动报 `jwt-secret 长度不足 32 字节` | `WMS_JWT_SECRET` 太短，HS256 要求 ≥ 32 字节 |
| 启动报 `.part.lock (系统找不到指定的路径)` | 未加 `-s maven-settings.xml`，Maven 用了全局配置里不存在的本地仓库 |
| 所有接口都返回 401 | 未登录或 Token 过期（默认 8 小时）；重新登录即可 |
| 明明有权限却返回 403 | 权限码拼写不符；或管理员刚改过权限，**需重新登录**才生效 |
| 页面菜单少了功能 | 当前角色确实没有该权限（可对照《鉴权中间件规范》第 4 节权限矩阵） |
| **点了「开始入库仿真 / 开始出库仿真」好像没反应，浏览器控制台也一片空白** | **这是正常的**：接口其实已经执行成功，前端**刻意不往浏览器控制台打印任何日志**（成功只更新界面，失败由统一 http 拦截器弹红色提示，源码中没有任何 `console.*`）。请看下面「怎么确认操作真的生效」小节 |
| 导出 CSV 用 Excel 打开中文乱码 | 使用系统的导出功能（已带 BOM）；不要用浏览器另存或第三方转换 |
| 建库位提示「层号超出货架层数上限」 | 货架层数不足，先改货架层数或降低层号 |
| 删仓库/货架提示「资源被引用」 | 需先删除下级数据（货架/库位），占用状态的库位需先释放货物 |
| 前端 `npm run dev` 起不来 | Node 版本需 ≥ 18；先 `npm install` |

### 5.1 怎么确认操作真的生效（浏览器控制台为什么是空的）

**前端刻意不往浏览器控制台打印任何日志**（`frontend/src/` 中没有任何 `console.*` 调用），这是有意的设计：

- **成功**：只更新界面状态，并在右上角弹一条绿色提示，例如
  `仿真完成：INB-003，方案 #37`；
- **失败**：由 `frontend/src/api/http.ts` 的响应拦截器**统一**弹出红色提示
  （401 会清登录态并跳登录页、403 提示无权限、422 展示业务错误信息），
  各页面里的 `catch { }` 是空的，避免重复弹窗——所以控制台同样不会出现报错堆栈。

因此判断一次操作是否生效，请按这三处看（以「开始入库仿真」为例）：

| 位置 | 看什么 |
| --- | --- |
| ① 页面右上角 | 绿色提示 `仿真完成：INB-xxx，方案 #xxx`；失败则是红色提示与业务错误码 |
| ② 页面往下滚 | 配置卡片**下方**会新增「仿真结果」卡片：方案编号、违规数、布局口径统计、**逐条选位理由**与平面图高亮。结果卡片在首屏之下，**没往下滚就容易以为「点了没反应」** |
| ③ 后端控制台 | 每次都会打印一行 `入库仿真完成 INB-xxx 策略=smart 仓库=1 条目=3 违规=0 方案=37(PLAN-20260928-003)`；出库仿真同理打印 `出库仿真完成 OUT-xxx 方案=... 订单=... 总路程=... 平均=... 耗时估算=...s` |
| ④ 旁证 | 切到「方案对比」页刷新，列表里会多出刚产出的方案（方案行数与编号立即增加） |

> 需要排查具体请求时，用浏览器 **Network（网络）** 面板看 `/api/v1/...` 的请求与响应体，
> 或直接看后端控制台——它会把每条 SQL 与业务日志都打出来（开发配置 `com.wms: DEBUG`）。

### 6.2 一键验收自检（对应上表 8 条验收标准）

### 附录 B：b、c 模块操作说明

> 以下页面均在侧边菜单「智能决策」「系统配置」分组下，菜单项按角色权限自动显隐（FR-RBAC-3）。

#### B-1 入库推荐（b，B-F1 / B-F2，界面需求 8.3）

**入口**：智能决策 → 入库推荐（需 `recommend:view`，admin / operator）

1. 选择仓库与货物（下拉框来自 API-017 / API-029，展示重量、周转频次、优先级）；
2. 点「生成推荐」（API-041）：按综合评分降序给出候选库位，并展开**四个分项得分**
   （重量 / 频次 / 优先级 / 其他）与**可读理由**（如「低层适配重货 + 靠近出库口」）；
3. 下方平面图**高亮全部候选库位**（B-F2，复用 c 的 C-F1 公共组件）；
4. 点「一键采用首位推荐」（API-043）完成入库，库位立即变为占用；
5. 想改变排序，到「权重与规则」页调权重后重新生成推荐（FR-2.3）。

#### B-2 权重与分层规则（b，B-F4，FR-2.3）

**入口**：系统配置 → 权重与规则（需 `config:manage`，仅 admin）

- **评分权重**（API-044/045）：四项之和必须为 1，页面顶部实时显示当前之和并标红提示；
- **库位分层规则**（API-046/047）：重货阈值、重货最高层号、归一化上限、黄金区半径、是否启用品类匹配；
  该规则同时作用于推荐引擎（硬过滤）与仿真引擎（软约束计数）；
- **参数校准**（API-048）：用表单里**尚未保存**的参数重新评分预览，用于对比「改参数的排序变化」，不落库；
- 保存后立刻生效，推荐与「智能推荐」策略都会使用新参数。

#### B-3 方案对比与报告（b，B-F3，FR-5.1 / FR-5.2）

**入口**：智能决策 → 方案对比（需 `compare:view`；报告导出按钮另需 `report:export`）

1. 选择仓库 → 方案列表（API-049）展示每个方案的总搬运路程 / 平均路程 / 高频货平均距离 /
   重货违规数 / 订单数；方案由「策略仿真」页产出；
2. 勾选 **≥2 个**方案 → 「对比所选方案」（API-051）：指标表格 + 柱状/折线对比图 + 自动生成的优化建议文字；
3. 每行右侧可导出该方案为基线（含其余方案）的对比报告：**MD / CSV**（API-053）。
   导出走带鉴权头的下载（`Authorization: Bearer`），不是裸链。

#### C-1 入库策略仿真（c，C-F3，FR-3）

**入口**：智能决策 → 策略仿真 →「① 入库策略仿真」（需 `sim:view` 查看；执行需 `sim:run`）

1. 顶部选仓库与**距离口径**（曼哈顿 / 欧氏 / 三维折线；选三维折线时可设层高）；
2. 选**入库策略**：随机 / 就近 / 分区 / 分级 / 智能推荐 / FIFO——列表由 API-054 动态返回，
   新增策略无需改前端；
3. 勾选入库明细并填数量（一库位一货物，故一项明细占一个库位）；
4. 点「开始入库仿真」（API-055）：得到 `INB-xxx` 与产出的**方案**（`planId`），
   表格逐条给出「分配库位 + 适配分 + 选择理由 + 告警」，平面图高亮本方案占用的库位；
5. 想换策略重跑，点「清空重置」（API-057）：清除本次仿真记录**及其方案**，基础数据不受影响。

> **点完怎么确认生效**：右上角会弹 `仿真完成：INB-xxx，方案 #xxx`，**往下滚**能看到新增的
> 「仿真结果」卡片（逐条选位理由 + 平面图高亮），后端控制台也会打印一行 `入库仿真完成 ...`。
> 浏览器控制台空白是正常的，原因见 §5.1。

> **重要口径**：仿真**不改动库位占用状态**（《数据库设计说明书》5.2「仿真需在不改库的前提下试算」），
> 只有「入库推荐」页的「一键采用」才会真正占用库位。
>
> **重货层位违规数**是**软约束**：随机/就近/分区/FIFO 可能把重货放到高层，命中的会给出红色告警
> 并计入该方案的违规数；智能推荐与分级存储会主动避开。若所有策略都强制过滤，这一对比指标会恒为 0。

#### C-2 出库仿真与路程统计（c，C-F5，FR-4）

**入口**：智能决策 → 策略仿真 →「② 出库仿真与统计」

1. **生成随机测试订单集**（API-062）：设数量、优先级范围、出库数量范围、随机种子
   （同种子必然生成同一批订单，便于复现与写报告）；
2. 选**拣选依据方案**（留空则按仓库当前真实占用拣选），设平均移动速度（格/秒）；
3. 点「开始出库仿真」（API-058）：订单按「优先级降序 + 下达时间升序」逐单拣选；
4. 查看统计卡片（总搬运路程 / 平均每单路程 / 高频货平均距离 / 耗时估算）与
   **前 20 单路程柱状图 + 平均线**（ECharts 公共组件）。

#### C-3 平面图与拣选路径可视化（c，C-F1 / C-F4）

**入口**：仓库总览（只读）与策略仿真页

- **平面图公共组件** `WarehouseLayout`（COM-5 冻结契约）三方共用：
  props 为 `locations` / `exit` / `highlight` / `path`（另有 `layer`、`cellSize`、`height`），
  emits 为 `location-click` / `location-hover`；
- 用 **Canvas** 绘制（万级库位下 DOM 方案会卡死）；图例区分空闲 / 占用 / 停用 / 高亮 / 出库口 / 路径；
- 仓库总览页支持**按层查看**并点击库位查看详情（编码、坐标、层号、状态、容量、距出库口距离）；
- 在策略仿真②的右下角**点击任一订单**即可在平面上绘制该订单的拣选路径
  （`库位 → 出库口` 折线，API-061）。
