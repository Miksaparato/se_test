## 1. 设计约定

| 项 | 约定 | 出处 |
| --- | --- | --- |
| 表名 | snake_case、**复数**：`warehouses`、`locations`、`turnover_rate` 同风格 | 《代码规范》2.2 |
| 字段名 | snake_case；实体自动映射为 Java camelCase（如 `turnover_rate` → `turnoverRate`） | 《代码规范》2.2 / 4.4 |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT`，MyBatis-Plus `@TableId(type = IdType.AUTO)` | 《代码规范》4.4 |
| 外键 | 统一 `xxx_id`；库位/货物等业务外键**均建约束**，避免脏数据 | 本设计 |
| 金额/重量 | 用 decimal 或明确精度；**重量用 `DECIMAL(12,3)`（kg）**，避免浮点误差 | 《代码规范》4.4 |
| 距离/路程 | 用 `DOUBLE`（曼哈顿距离口径见 COM-6，由 c 牵头统一） | 《代码规范》4.4 |
| 时间 | 统一 UTC 存储，`DATETIME(3)`；接口层按 ISO 8601 UTC 输出（`2026-09-10T09:00:00.000Z`） | 《代码规范》6 / 4.4 |
| 布尔 | `TINYINT(1)`，字段名 `is_` 前缀（如 `is_builtin`、`is_active`） | 《代码规范》2.2 |
| 枚举 | `VARCHAR(16)` + 取值范围注释（不用 MySQL ENUM，便于扩展与 MyBatis-Plus 映射） | 本设计 |
| JSON | `JSON` 类型；**写入必须为合法 JSON**，禁止存字符串字面量 | 本设计 |
| 字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci`，中文界面与 emoji 安全 | NFR-2 |

### 1.2 实体关系

```
warehouses 1 ──< racks 1 ──< locations
warehouses 1 ──< plans                            （plans 由 c 的仿真写入、b 读取）
skus       1 ──< orders
skus       1 ──< locations.occupied_sku_id         （当前占用货物，可空）
users      M ──< user_roles >── M roles
roles      M ──< role_permissions >── M permissions
users      1 ──< audit_logs
```

> 说明：`warehouses → skus`、`warehouses → orders` **不建物理外键**，与《需求文档》6.1 的层级一致（仓库下直接挂载货物与订单，见 FR-1.2/FR-1.3 无仓库入参）。

### 2.2 `racks` 货架

| 字段 | 类型 | 允许空 | 默认 | 说明 |
| --- | --- | :-: | --- | --- |
| `id` | BIGINT UNSIGNED | 否 | AUTO | 主键 |
| `warehouse_id` | BIGINT UNSIGNED | 否 | — | 所属仓库，FK → `warehouses.id` |
| `code` | VARCHAR(32) | 否 | — | 货架编码，如 `A-01`；仓库内唯一 |
| `aisle` | VARCHAR(16) | 否 | — | 巷道（A/B/C…），库位编码第 1 段 |
| `column_count` | INT UNSIGNED | 否 | 1 | 列数，库位编码第 2 段 |
| `layer_count` | INT UNSIGNED | 否 | 1 | 层数，库位编码第 3 段 |
| `x` | INT | 是 | NULL | 货架基准平面坐标 x（供平面图渲染，C-F1） |
| `y` | INT | 是 | NULL | 货架基准平面坐标 y |
| `orientation` | VARCHAR(16) | 否 | 'row' | 库位排布方向：`row` 沿 x 轴递增 / `column` 沿 y 轴递增 |
| `created_at` | DATETIME(3) | 否 | CURRENT_TIMESTAMP(3) | 创建时间 |

- 唯一键：`uk_racks_warehouse_code (warehouse_id, code)`
- 普通索引：`idx_racks_warehouse (warehouse_id)`
- 外键：`fk_racks_warehouse_id` → `warehouses(id) ON DELETE RESTRICT`
- 说明：`column_count / layer_count` 是**建货架时声明的规模**；`locations` 表存**实际库位实例**。批量生成库位由 API-025 或建货架时的联动逻辑完成（a 的第 6 步）。

### 2.3 `locations` 库位

| 字段 | 类型 | 允许空 | 默认 | 说明 |
| --- | --- | :-: | --- | --- |
| `id` | BIGINT UNSIGNED | 否 | AUTO | 主键 |
| `rack_id` | BIGINT UNSIGNED | 否 | — | 所属货架，FK → `racks.id` |
| `warehouse_id` | BIGINT UNSIGNED | 否 | — | 冗余仓库 id，**为避免万库位查询回表 JOIN（NFR-1）**；由 a 的业务代码保证与货架一致 |
| `code` | VARCHAR(32) | 否 | — | 库位唯一编码「巷道-列-层」，如 `A-01-03-02`，**全局唯一**（FR-1.1 验收 1） |
| `x` | INT | 否 | — | 平面坐标 x（曼哈顿距离 `|x1-x2| + |y1-y2|` 的起点） |
| `y` | INT | 否 | — | 平面坐标 y |
| `layer` | INT UNSIGNED | 否 | 1 | 层号，**从 1 开始，层号越小越靠地面**（评分模型 `S_weight` 依据） |
| `status` | VARCHAR(16) | 否 | 'free' | 库位状态：`free` 空闲 / `occupied` 占用 / `disabled` 停用 |
| `capacity` | DECIMAL(12,3) | 否 | 100.000 | 库位容量（体积口径，与 SKU 尺寸校验，见 5.2） |
| `occupied_sku_id` | BIGINT UNSIGNED | 是 | NULL | 当前占用货物 id；**`status='occupied'` 时必须非空** |
| `created_at` | DATETIME(3) | 否 | CURRENT_TIMESTAMP(3) | 创建时间 |
| `updated_at` | DATETIME(3) | 否 | 自动更新 | 更新时间 |

- 唯一键：`uk_locations_code (code)`
- 普通索引：`idx_locations_warehouse_status (warehouse_id, status)`（推荐引擎取「全部空闲库位」主查询路径）、`idx_locations_rack (rack_id)`、`idx_locations_occupied_sku (occupied_sku_id)`
- 外键：`fk_locations_rack_id` → `racks(id) ON DELETE RESTRICT`；`fk_locations_warehouse_id` → `warehouses(id) ON DELETE RESTRICT`；`fk_locations_occupied_sku_id` → `skus(id) ON DELETE RESTRICT`

> **给 b、c 的冻结契约（重点）**
> 1. `status` 取值为**小写字符串** `free` / `occupied` / `disabled`，接口层同名输出（《接口文档》API-021 示例即 `"status": "free"`）。
> 2. 推荐/仿真**只消费 `status = 'free'`** 的库位；`disabled` 必须排除。
> 3. `layer` 与 `x / y` 是评分与距离的**唯一数据来源**，直接读 `locations`，不要从 `racks` 推导。
> 4. `warehouse_id` 是 a 维护的冗余字段，b、c 可直接用它一次查出某仓库全部库位，无需 JOIN `racks`。
> 5. `capacity` 为**体积**口径；SKU 体积 = `size.length × size.width × size.height`。

### 2.4 `skus` 货物

| 字段 | 类型 | 允许空 | 默认 | 说明 |
| --- | --- | :-: | --- | --- |
| `id` | BIGINT UNSIGNED | 否 | AUTO | 主键 |
| `code` | VARCHAR(32) | 否 | — | SKU 编码，**唯一**，如 `SKU-001`（API-030 的 `skuCode`） |
| `name` | VARCHAR(64) | 否 | — | 货物名称 |
| `weight` | DECIMAL(12,3) | 否 | 0 | 重量（kg）→ 评分 `S_weight` |
| `turnover_rate` | DECIMAL(12,4) | 否 | 0 | 周转频次（次/单位时间）→ 评分 `S_freq`；字段名沿用《需求文档》6.1 |
| `priority` | INT | 否 | 1 | 出库优先级，建议 1~5，越大越紧急 → 评分 `S_priority` |
| `category` | VARCHAR(32) | 是 | NULL | 品类，如「电子」→ 评分 `S_other` 的分区匹配项 |
| `size` | JSON | 是 | NULL | 尺寸 `{"length":30,"width":20,"height":10}`（与《接口文档》API-030 完全一致） |
| `remark` | VARCHAR(255) | 是 | NULL | 备注 |
| `created_at` | DATETIME(3) | 否 | CURRENT_TIMESTAMP(3) | 创建时间 |
| `updated_at` | DATETIME(3) | 否 | 自动更新 | 更新时间 |

- 唯一键：`uk_skus_code (code)`
- 普通索引：`idx_skus_category (category)`
- `weight / turnover_rate / priority` 是**推荐引擎（b）与仿真引擎（c）的核心输入**（《接口文档》第 6 节标注），字段名与口径冻结。
- `priority` 的取值范围 1~5 由业务校验（API-030/031）保证，数据库不设 CHECK，便于后续放宽。

> **给 b、c 的冻结契约（`skus`）**
> 1. 接口 JSON 字段名为 `skuCode`（← `code`）、`weight`、`turnoverRate`（← `turnover_rate`）、`priority`、`category`、`size`。
> 2. `size` 为 JSON 列，**结构固定为** `{"length":30,"width":20,"height":10}`（单位与仓库坐标一致）；
>    实体侧映射为 `com.wms.domain.entity.type.SkuSize`（record），随接口附带派生字段 `volume = length×width×height`，
>    供容量校验直接使用（`locations.capacity` ≥ `volume`）。
> 3. `weight` 与 `turnoverRate` 用 `BigDecimal` 存取，接口以 JSON 数字返回（如 `0.9` 不会变成 `0.9000`）。
> 4. 排序/比较请用 `BigDecimal.compareTo`，不要用 `equals`（精度不同会误判）。
> 5. 删除保护：被库位占用（`locations.occupied_sku_id`）或被订单引用时，`DELETE /api/v1/skus/{id}` 返回 **42210**；
>    b、c 若需要「先清理再删」，请先释放库位/订单引用。

- 唯一键：`uk_plans_plan_no (plan_no)`

- 外键：`fk_plans_warehouse_id` → `warehouses(id) ON DELETE RESTRICT`；`fk_plans_created_by` → `users(id) ON DELETE SET NULL`

**`location_map` 结构（c 写、b 读，冻结）**：库位为键，便于 b 做方案对比与占用复原。

```json
{
  "1001": { "skuId": 3, "quantity": 20 },
  "1002": { "skuId": 5, "quantity": 10 }
}
```

**`result` 结构（c 写、b 读，冻结）**：字段名与《接口文档》API-051 对比指标逐一对齐。

```json
{
  "totalDistance": 5820,
  "avgDistance": 116.4,
  "hotAvgDistance": 210.3,
  "violations": 5,
  "orderCount": 50,
  "estimatedTime": 3880
}
```

| JSON 键 | 类型 | 含义 | 对比接口字段 |
| --- | --- | :-: | --- |
| `totalDistance` | double | 总搬运路程（曼哈顿口径，COM-6） | `totalDistance` |
| `avgDistance` | double | 平均每单路程 | `avgDistance` |
| `hotAvgDistance` | double | 高频货平均距离 | `hotAvgDistance` |
| `violations` | int | 重货层位违规数（阈值见 5.2） | `violations` |
| `orderCount` | int | 参与出库仿真的订单数 | — |
| `estimatedTime` | double | 耗时估算（秒，速度可配） | `estimatedTime` |

> **未设字段的原因**：方案不绑定 `simulation` 表（《需求文档》6.1 未定义仿真记录表）。仿真明细（每次选位与理由、拣选路径）由 c 在 `simulation/` 模块内保存，方案只落库汇总快照。

## 3. RBAC 表（V2）

### 3.1 `users` 用户

| 字段 | 类型 | 允许空 | 默认 | 说明 |
| --- | --- | :-: | --- | --- |
| `id` | BIGINT UNSIGNED | 否 | AUTO | 主键 |
| `account` | VARCHAR(32) | 否 | — | 登录账号，**唯一** |
| `password` | VARCHAR(100) | 否 | — | **BCrypt 哈希**（`$2a$10$...`，60 字符），永不返回给前端（NFR-6） |
| `name` | VARCHAR(64) | 是 | NULL | 姓名/昵称，对应 API-001 返回的 `name` |
| `email` | VARCHAR(128) | 是 | NULL | 邮箱 |
| `phone` | VARCHAR(32) | 是 | NULL | 手机号 |
| `status` | VARCHAR(16) | 否 | 'active' | 账号状态：`active` 启用 / `disabled` 禁用（FR-RBAC-1） |
| `last_login_at` | DATETIME(3) | 是 | NULL | 最近登录时间 |
| `remark` | VARCHAR(255) | 是 | NULL | 备注 |
| `created_by` | BIGINT UNSIGNED | 是 | NULL | 创建人用户 id（**不建外键**，避免 `users` 自引用） |
| `created_at` | DATETIME(3) | 否 | CURRENT_TIMESTAMP(3) | 创建时间 |
| `updated_at` | DATETIME(3) | 否 | 自动更新 | 更新时间 |

- 唯一键：`uk_users_account (account)`
- 索引：`idx_users_status (status)`
- 关联：`user_roles`（多对多）——**取代《需求文档》6.1 的 `users.role_ids` JSON 列**，理由见 3.5。

### 3.5 `user_roles` 用户-角色关联

| 字段 | 类型 | 允许空 | 说明 |

- **设计取舍（已与用户确认）**：《需求文档》6.1 写 `users.role_ids` 为 JSON，本设计**规范化为关联表**，因为 RBAC 的授权校验（`@PreAuthorize` 取权限集合）必须按 userId → roleId → permissionCode 关联查询，JSON 列无法建索引、需应用层解析，与 NFR-1/NFR-6 冲突。
  对外接口**仍返回 `roles: ["admin"]` 数组**（《接口文档》API-001 示例），契约不变。

## 5. 与接口/算法的口径对齐（给 b、c 的对接要点）

### 5.1 服务端命名转换

| 层 | 命名 | 示例 |
| --- | --- | --- |
| 数据库 | snake_case | `turnover_rate`、`occupied_sku_id` |
| Java 实体/字段 | camelCase（MyBatis-Plus 自动映射） | `turnoverRate`、`occupiedSkuId` |
| REST JSON | camelCase（与《接口文档》示例一致） | `turnoverRate`、`skuCode` |

- 【必须】JSON 字段名**必须**与《接口文档》示例一致，禁止前端/后端私自改名（《代码规范》5.4）。
- 例外：`locations` 直接以实体返回的列表接口（API-027）字段为 `code / x / y / layer / status / capacity`，与《接口文档》API-021 示例一致，无驼峰转换歧义。

### 5.2 约束的落库与校验分工

| 约束（《需求文档》5.4） | 数据库层 | 应用层（a / b / c） |
| --- | --- | --- |
| 一库位一货物 | `locations.occupied_sku_id` 单值 + `status` 枚举 | 采用推荐/仿真写库前校验 `status='free'`，否则抛 `42201 库位已占用` |
| 重货禁止超过预设层高（阈值可配） | 不落库（阈值属配置） | 推荐引擎（b，B-B4 分层规则）与约束校验（c，C-B7）按配置阈值判定；方案对比统计 `violations` |
| 尺寸不得超出库位容量 | 不落库（尺寸在 JSON） | SKU 体积 = `size.length × size.width × size.height` ≤ `locations.capacity`，违规抛 `422` |

> 说明：重货阈值与容量校验**刻意不落库**，因为阈值可配置（FR-2.3）、且仿真需在不改库的前提下试算。数据库只保证「结构合法」，业务规则由应用层统一判定，避免 DB 报错信息无法映射到错误码。

### 5.3 索引与性能（NFR-1：万库位 ≤ 5s）

| 场景 | 查询 | 依赖索引 |
| --- | --- | --- |
| 推荐取全部空闲库位 | `WHERE warehouse_id = ? AND status = 'free'` | `idx_locations_warehouse_status` |
| 库位按货架/状态过滤（API-027） | `WHERE rack_id = ?` / `status = ?` | `idx_locations_rack`、`idx_locations_warehouse_status` |
| 出库仿真订单排序 | `WHERE status='pending' ORDER BY priority DESC, placed_at ASC` | `idx_orders_status_priority_placed` |
| 鉴权取权限集合 | `users → user_roles → role_permissions → permissions` | `uk_users_account`、`uk_user_roles`、`idx_role_permissions_permission` |
| 方案对比列表 | `WHERE warehouse_id = ?` | `idx_plans_warehouse` |

- 【必须】a 在实现中禁止循环单条查询（N+1），批量取数用 `selectBatchIds` / `saveBatch`（《代码规范》4.4）。
- 库位批量生成（一个货架 N 列 × M 层）必须用 `saveBatch`，禁止循环 `insert`。

### 6.1 与源文档数据字典的差异说明（须 b、c 确认）

| # | 《需求文档》6.1 原写法 | 本设计的处理 | 理由 |
| :-: | --- | --- | --- |
| 1 | `User.role_ids` JSON 列 | 规范化为 `user_roles` 关联表 | 授权校验需关联查询、需索引；对外 JSON 契约仍为 `roles: []` |
| 2 | `Role.permissions` JSON 列 | 规范化为 `role_permissions` 关联表 | 同上；API-014 仍以 `permissions: []` 全量覆盖 |
| 3 | `Warehouse` 无出库口字段 | 增加 `exit_x / exit_y / exit_layer` | 《接口文档》API-021 返回 `exit {x,y}`，距离计算（COM-6）必须知道出库口坐标 |
| 4 | `Location` 未提及所属仓库 | 增加冗余列 `warehouse_id` | 避免万库位查询 JOIN `racks`（NFR-1）；接口不影响（嵌套在 rack 下返回） |
| 5 | `Plan` 无仓库/编号/展示名 | 增加 `plan_no / name / warehouse_id / simulation_id / strategy_name` | 方案列表（API-049）需标识与仓库范围；`simulation_id` 对应接口 `simulationId` |
| 6 | `Location.status` 仅 `free/occupied` | 增加 `disabled` | 支持库位停用（不参与推荐/仿真），扩展枚举不影响既有取值 |
| 7 | `Order.status` 为 Enum 未列值 | 明确 `pending/picking/completed/cancelled` | 接口示例出现 `pending`；补齐状态机便于 API-033 过滤 |
| 8 | 未定义操作审计表 | 增加 `audit_logs`（可选） | 《代码规范》4.6 要求关键路径记录操作人/资源/结果 |
| 9 | `users` 未定义创建人 | 增加 `created_by`（不建外键） | 便于追溯「谁创建了该账号」；自引用外键会带来删除顺序麻烦 |
| 10 | 时间戳策略未说明 | 数据库默认值 + 应用侧 `WmsMetaObjectHandler` 双保险 | MyBatis-Plus 的 `insert` 会写出未赋值字段为 NULL，覆盖数据库默认值，故由应用统一填充 `created_at`/`updated_at` |
