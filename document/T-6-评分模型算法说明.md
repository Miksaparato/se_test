## 1. 概述

入库推荐的目标：给定一个待入库货物（SKU）与目标仓库，对所有**空闲库位**计算综合评分，按评分**降序**给出推荐列表，并附可读的推荐理由。评分过程遵循以下原则：

1. **多因子加权**：综合重量适配、周转频次、出库优先级、品类/连续性四类因子。
2. **归一化**：各分项得分归一化到 `[0,1]`，权重之和为 `1`，总分天然落在 `[0,1]`。
3. **硬约束优先**：评分前先过滤掉违反「重货层高」约束的库位（算法 5.4）。
4. **无状态可测**：引擎为纯 Java 服务，不依赖 Spring 上下文副作用（NFR-4）。

---

## 2. 综合评分模型

对候选库位 `L`，综合得分：

```
Score(L) = W_w · S_weight(L) + W_f · S_freq(L) + W_p · S_priority(L) + W_o · S_other(L)
```

| 权重 | 含义 | 默认值 |
| --- | --- | ---: |
| W_w | 重量分项权重 | 0.30 |
| W_f | 周转频次分项权重 | 0.40 |
| W_p | 出库优先级分项权重 | 0.20 |
| W_o | 其他分项权重 | 0.10 |

- 权重之和必须为 `1`（`ScoreWeightConfig.validate()` 校验，否则抛 `WEIGHT_SUM_INVALID`）。
- 权重可通过 API-045 动态调整；各分项得分通过 API-041 响应中的 `subScores` 输出（**加权后**值）。

---

## 3. 分项得分公式

所有公式中的 `clamp(v) = max(0, min(1, v))`，用于把归一化值截断到 `[0,1]`。

### 3.1 重量分项 S_weight（低层适配重货）

```
S_weight = clamp(weight / maxWeightNorm) × layerSuitability(layer)

layerSuitability(layer) = (maxLayer - layer + 1) / maxLayer
```

- `weight`：货物重量（kg）；`maxWeightNorm`：重量归一化上限（默认 200）。
- `layer`：库位层号，`1` 为最底层，越大越高；`maxLayer`：本次候选库位的最大层号。
- 含义：货物越重、库位越靠底层（层号小），`S_weight` 越高。层号 `1`（最底层）的 `layerSuitability` 为 `1`。

### 3.2 周转频次分项 S_freq（高频近出库口）

```
S_freq = clamp(turnoverRate / maxTurnover) × proximity(x, y)
```

- `turnoverRate`：周转频次（归一化到 `[0,1]`）；`maxTurnover`：频次归一化上限（默认 1.0）。
- 含义：周转越频繁、库位离出库口越近，`S_freq` 越高。

### 3.3 出库优先级分项 S_priority（高优先级近出库口）

```
S_priority = clamp(priority / maxPriority) × proximity(x, y)
```

- `priority`：出库优先级（1~5）；`maxPriority`：优先级上限（默认 5）。
- 含义：优先级越高、库位越靠近出库口，`S_priority` 越高。

### 3.4 其他分项 S_other（品类匹配 + 空位连续性）

```
S_other = 0.6 × categoryMatch + 0.4 × continuity
```

- `categoryMatch`：
  - 库位分区品类与货物品类一致 → `1.0`
  - 库位无分区约束、或未启用品类匹配 → `0.5`（中性）
  - 不一致 → `0.0`
- `continuity`：库位同层正交四邻（上下左右）中被占用库位的比例，取值 `[0,1]`。奖励「填满连续空位」，避免货架碎片化。

### 3.5 就近度 proximity

```
proximity(x, y) = (dMax - d(x,y)) / (dMax - dMin)

d(x,y) = |x - exitX| + |y - exitY|          （曼哈顿距离，见 §5）
```

- `dMin` / `dMax`：本次候选库位中到出库口距离的最小/最大值。
- 当 `dMax == dMin`（所有候选等距）时，`proximity` 取 `1.0`。
- 含义：离出库口最近者 `proximity = 1`，最远者 `proximity = 0`。

## 4. 硬约束（算法 5.4）

评分前对空闲库位做硬约束过滤：

> **重货禁止分配到超过预设层高的库位。**

```
allowsHeavyOnLayer(weight, layer) =
    weight < heavyWeightThreshold          → true（轻货不受限）
    weight >= heavyWeightThreshold && layer <= maxLayerForHeavy → true
    否则                                    → false（过滤）
```

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| heavyWeightThreshold | 100 | 重货判定阈值（kg） |
| maxLayerForHeavy | 2 | 重货允许的最高层号（1 为最底层） |

- 过滤后若无可用库位，推荐接口返回 `NO_ELIGIBLE_LOCATION`（42204）。

## 5. 距离口径（COM-6，成员 c 牵头）

本模块所有距离计算统一使用**曼哈顿距离**：

```
d((x1,y1), (x2,y2)) = |x1 - x2| + |y1 - y2|
```

- 出库口坐标为仓库的 `(exitX, exitY)`，作为距离原点。
- 本模块仅在 `proximity` 中以内联方式使用该口径；正式距离工具类由成员 c 提供 `DistanceUtil.manhattan`，联调后替换（遵守 COM-6，禁止各处自行实现）。

---

## 6. 排序与输出

1. 硬约束过滤 → 得到候选库位集合。
2. 构建 `ScoringContext`（缓存出库口、maxLayer、min/max 距离等共享量，避免重复计算，满足 NFR-1）。
3. 对每个候选库位计算加权总分与各分项加权得分。
4. 按总分**降序**排序，取前 `topN`（默认 10）作为推荐列表。
5. 每个推荐项输出：`locationId`、`code`、`score`、`subScores`（weight/freq/priority/other 加权值）、`reason`。

**推荐理由**（`ReasonBuilder`）基于分项原始得分阈值拼装中文短语，例如：
「低层适配重货 + 靠近出库口利于高频 + 品类匹配 + 空位连续」，无命中时输出「综合评分最优」。

## 7. 示例

以 `SKU-001 高频电子元件`（重量 50kg、频次 0.9、优先级 5、品类「电子」）为例，出库口 `(0,0)`：

| 库位 | 层 | 距出库口 | S_weight | S_freq | S_priority | S_other | 总分 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A-01-01-01 | 1 | 4 | 0.25 | 0.36 | 0.18 | 0.08 | **0.87** |
| A-03-03-03 | 3 | 12 | 0.08 | 0.10 | 0.05 | 0.06 | 0.29 |

- 低层库位因 `layerSuitability` 高、且离出库口近，综合得分显著更高，被排在前列。
- 若货物改为 `SKU-002 重型机械`（180kg），层号 3 的库位会被硬约束过滤（180 ≥ 100 且 3 > 2）。

## 9. 性能（NFR-1）

- 引擎单次计算复杂度 `O(N)`（N 为候选库位），`ScoringContext` 预计算共享量避免重复。
- 单测 `PerformanceTest` 覆盖**万库位规模 ≤ 5s**：1 万空闲库位下评分 < 5s（实测远低于上限）。
