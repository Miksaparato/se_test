## 2. 通用约定（全员）

### 2.1 字符编码与换行

- 【必须】所有源码、配置、SQL、Markdown 统一 **UTF-8** 编码，无 BOM。
- 【必须】行尾统一 LF，文件末尾保留一个空行。

### 2.2 命名总则

| 场景 | 风格 | 示例 |
| --- | --- | --- |
| Java 类 / 接口 / 枚举 | PascalCase | `InboundStrategy`、`ScoringEngine` |
| Java 方法 / 变量 | camelCase | `scoreLocation`、`totalDistance` |
| Java 常量 | UPPER_SNAKE_CASE | `DEFAULT_WEIGHTS` |
| Java 包名 | 全小写、点分隔 | `com.wms.recommend` |
| TS/JS 变量/函数 | camelCase | `fetchRecommendations` |
| TS/JS 组件/类型/接口 | PascalCase | `WarehouseLayout.vue`、`type ScoreResult` |
| REST 路径 | kebab-case，资源复数 | `/simulations/inbound` |
| 数据库表/字段 | snake_case，表名复数 | `locations`、`turnover_rate` |
| Git 分支 | 见第 2.5 节 | `feature/a-rbac` |

- 【必须】命名**见名知意**，禁止无意义缩写（`tmp`、`x1`、`data1` 除外循环变量等约定场景）。
- 【推荐】布尔变量用 `is/has/can` 前缀：`isOccupied`、`hasPermission`。

### 2.3 注释与文档

- 【必须】后端公共类/方法用 **Javadoc** 说明「做什么、入参、返回、抛错」。
- 【必须】核心算法（评分模型、距离计算、策略、约束校验）必须有 Javadoc 并附**公式或口径**（如曼哈顿距离 `|x1-x2|+|y1-y2|`），对应 NFR-8 算法说明文档。
- 【必须】`TODO` 必须带责任人与编号：`// TODO(a): 补充重货层高校验（C-B7）`。
- 【推荐】前端组件头部注释说明 props/emits 用途。

### 2.4 Git 提交规范

**【必须】** 采用 Conventional Commits：

```
<type>(<scope>): <subject>
```

| type | 含义 | scope | 含义 |
| --- | --- | --- | --- |
| feat | 新功能 | data / rbac | a 的基础数据 / 权限 |
| fix | 修复 | recommend / compare | b 的推荐 / 对比 |
| docs | 文档 | sim / stats | c 的仿真 / 统计 |
| refactor | 重构 | common | 公共/脚手架 |
| test | 测试 | — | — |
| perf / chore | 优化 / 杂项 | — | — |

示例：

```
feat(rbac): 实现 Spring Security 鉴权与 JWT 过滤链（A-B8）
feat(recommend): 评分模型权重归一化（B-B1/B-B3）
test(sim): 补充曼哈顿距离单元测试（C-B5）
```

### 2.5 Git 分支模型

- 【必须】`main`（稳定）← `dev`（集成）← `feature/xxx`（开发）。
- 【必须】功能分支按开发者前缀命名：`feature/a-<模块>`、`feature/b-<模块>`、`feature/c-<模块>`。
- 【必须】禁止直接向 `main` 提交；`dev` 合并需通过 Code Review。
- 【推荐】小步提交，一个提交只做一件事。

## 4. 后端规范（Java + Spring Boot）

### 4.1 分层架构

**【必须】** 每个模块按「Controller → Service → Mapper」分层，禁止在 Controller 里写业务逻辑：

```
Controller（参数校验、权限注解、协议转换） → Service（业务逻辑） → Mapper（数据访问）
```

```java
@RestController
@RequestMapping("/api/v1/users")
public class UserController {

    private final UserService userService;

    @GetMapping
    @PreAuthorize("hasAuthority('user:manage')")
    public ApiResponse<PageResult<UserVO>> list(
            @RequestParam(defaultValue = "1") int page,
            @RequestParam(defaultValue = "20") int pageSize) {
        return ApiResponse.ok(userService.listUsers(page, pageSize));
    }
}
```

- 【必须】Controller 只做参数接收、`@Valid` 校验、权限注解、调用 Service、封装响应。
- 【必须】Service 面向业务，可被其他模块 Service 复用；禁止模块间直接调用彼此的 Controller 或 Mapper。

### 4.2 统一响应与错误处理

**【必须】** 统一响应结构，禁止手写散装 `Map`（对应《接口文档》1.2）：

```java
// common/ApiResponse.java
public record ApiResponse<T>(int code, String message, T data) {
    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(0, "success", data);
    }
    public static <T> ApiResponse<T> fail(int code, String message) {
        return new ApiResponse<>(code, message, null);
    }
}
```

**【必须】** 业务错误通过 `BizException` + `@RestControllerAdvice` 全局异常处理器抛出，错误码与 HTTP 状态码对齐：

| 错误码段 | HTTP | 含义 | 示例 |
| --- | --- | --- | --- |
| 400xx | 400 | 参数校验失败 | 40001 缺少必填字段 |
| 401xx | 401 | 未认证 | 40101 Token 失效 |
| 403xx | 403 | 越权 | 40301 无该操作权限 |
| 404xx | 404 | 资源不存在 | 40401 库位不存在 |
| 422xx | 422 | 业务规则 | 42201 库位已占用、42202 重货层高违规 |
| 500xx | 500 | 系统异常 | 50001 数据库错误 |

```java
// common/ErrorCode.java
public enum ErrorCode {
    PARAM_INVALID(40001, "参数校验失败"),
    UNAUTHORIZED(40101, "Token 失效"),
    FORBIDDEN(40301, "无该操作权限"),
    NOT_FOUND(40401, "资源不存在"),
    LOCATION_OCCUPIED(42201, "库位已占用"),
    WEIGHT_LAYER_VIOLATION(42202, "重货层高违规"),
    SYSTEM_ERROR(50001, "系统异常");
    // getter: code / message
}

// common/BizException.java
public class BizException extends RuntimeException {
    private final int code;
    public BizException(ErrorCode ec) { super(ec.getMessage()); this.code = ec.getCode(); }
}

// 业务代码抛出
throw new BizException(ErrorCode.WEIGHT_LAYER_VIOLATION);
```

```java
// common/GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BizException.class)
    public ResponseEntity<ApiResponse<Void>> handleBiz(BizException e) {
        return ResponseEntity.status(toHttp(e.getCode()))
                .body(ApiResponse.fail(e.getCode(), e.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValid(MethodArgumentNotValidException e) {
        return ApiResponse.fail(ErrorCode.PARAM_INVALID.getCode(),
                e.getBindingResult().getFieldErrors().get(0).getDefaultMessage());
    }
}
```

### 4.3 鉴权（a，A-B8）

**【必须】** 鉴权统一由 `a` 提供的 Spring Security 配置实现，业务接口用 `@PreAuthorize("hasAuthority('权限码')")` 声明权限，禁止在业务代码里自行判断：

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/auth/login").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}
```

- `JwtAuthFilter` 解析 `Authorization: Bearer <token>`，将用户权限码装入 `GrantedAuthority`，供 `@PreAuthorize` 校验。
- 权限码必须来自《接口文档》1.4 清单（`user:manage`、`sku:manage`、`recommend:view`、`sim:run` 等），禁止自行发明；新增权限须由 a 更新权限清单（API-015）。
- 【必须】前端权限显隐仅作体验优化，**后端 Spring Security 强制鉴权是唯一安全边界**（FR-RBAC-3）。

### 4.4 数据库访问（MyBatis-Plus）

- 【必须】实体用 `@TableName`（表名复数 snake_case）、主键用 `@TableId`、字段映射用 `@TableField`；未显式标注的字段按驼峰转下划线自动映射，与《接口文档》数据模型一致。
- 【必须】Mapper 继承 `BaseMapper<T>`，用 `@Mapper` 标注；复杂 SQL 统一写 XML（`resources/mapper/*.xml`），禁止在业务代码里拼字符串 SQL。
- 【必须】写操作必须 `@Transactional`；批量写用 `saveBatch`/`updateBatchById`，批量读用 `selectBatchIds`，注意性能（NFR-1）。
- 【必须】查询优先用 `LambdaQueryWrapper`（lambda 引用字段，避免硬编码列名）；分页统一用 `Page<T>` + `PaginationInnerInterceptor` 分页插件。
- 【必须】禁止在循环里逐条查询（N+1）：先 `selectBatchIds` 或自定义 XML 一次取齐，再在内存用 `Map` 组装关联。

```java
// domain/entity/Location.java
@TableName("locations")
public class Location {
    @TableId(type = IdType.AUTO)
    private Long id;

    @TableField("warehouse_id")
    private Long warehouseId;

    @TableField("turnover_rate")
    private Double turnoverRate;
    // getter/setter
}

// domain/mapper/LocationMapper.java
@Mapper
public interface LocationMapper extends BaseMapper<Location> { }

// service 层用法（LambdaQueryWrapper + 分页）
LambdaQueryWrapper<Location> qw = Wrappers.<Location>lambdaQuery()
        .eq(Location::getWarehouseId, warehouseId)
        .eq(Location::getStatus, "free");
List<Location> freeLocations = locationMapper.selectList(qw);

Page<Location> page = locationMapper.selectPage(
        new Page<>(1, 20),
        Wrappers.<Location>lambdaQuery().orderByAsc(Location::getId));
```

- 【必须】金额/重量用 `BigDecimal` 或明确 float 精度；距离/路程用 `double`；时间统一 UTC（ISO 8601，`LocalDateTime`/`Instant` 约定时区）。
- 【必须】数据库结构变更通过 Flyway 版本化脚本（`db/migration/V*.sql`），由 a 牵头评审，禁止直接改库不落脚本。

### 4.5 算法模块规范（b 推荐引擎、c 仿真引擎）

**【必须】** 算法以**无状态 Service 或纯方法**实现，不依赖 Spring 上下文副作用，便于单元测试（NFR-4）：

```java
// recommend/engine/ScoringEngine.java（b）
@Service
public class ScoringEngine {

    /** 计算单个库位综合得分。
     *  公式: Score = W_w*S_weight + W_f*S_freq + W_p*S_priority + W_o*S_other
     *  各分项归一化到 [0,1]。
     */
    public ScoreResult score(Location location, Sku sku, Weights weights, Rules rules) {
        double score = weights.weight() * scoreWeight(location, sku)
                     + weights.freq()  * scoreFreq(location, sku)
                     + weights.priority() * scorePriority(location, sku)
                     + weights.other() * scoreOther(location, sku);
        return new ScoreResult(score, subScores);
    }
}
```

**【必须】** 策略采用**接口 + 注册表**的插件式设计（NFR-3），新增策略只需新增实现并注册：

```java
// simulation/strategy/InboundStrategy.java（c）
public interface InboundStrategy {
    String name();
    List<Assignment> assign(List<SkuItem> items, List<Location> locations, SimContext ctx);
}

// simulation/strategy/StrategyRegistry.java
@Component
public class StrategyRegistry {
    private final Map<String, InboundStrategy> strategies;

    public StrategyRegistry(List<InboundStrategy> all) {   // Spring 注入全部实现
        this.strategies = all.stream()
            .collect(Collectors.toMap(InboundStrategy::name, s -> s));
    }
    public InboundStrategy get(String name) { return strategies.get(name); }
}
```

- 【必须】距离计算统一走 c 提供的 `DistanceUtil.manhattan(a, b)`，禁止各处自行实现（对应 COM-6）。
- 【必须】`smart` 策略通过 b 的 `ScoringEngine` 复用评分，禁止复制评分逻辑。

### 4.6 日志

- 【必须】使用 SLF4J（Lombok `@Slf4j` 或手写 `LoggerFactory.getLogger`），按模块输出结构化日志。
- 【必须】关键路径（入库/出库/推荐/越权）记录操作人、资源、结果；禁止记录密码、Token 等敏感信息。

### 4.7 单元测试（JUnit 5）

- 【必须】核心算法必须覆盖单元测试：评分模型（b）、策略与距离/约束（c）、CRUD 与鉴权越权（a）。
- 【必须】算法测试用纯 JUnit 5（不启动 Spring 上下文），接口测试用 `@WebMvcTest` + Mockito。
- 【必须】测试类命名 `XxxTest`，测试方法用 `should_...` 描述行为。
- 【推荐】算法模块覆盖率 ≥ 80%；至少覆盖正常、边界、异常三类用例。

```java
class DistanceUtilTest {

    @Test
    void should_compute_manhattan_distance() {
        assertEquals(6.0, DistanceUtil.manhattan(new Point(3, 2), new Point(0, 5)));
    }
}
```

## 5. 前端规范（Vue 3 + TypeScript）

### 5.1 组件规范

- 【必须】使用 `<script setup lang="ts">` 组合式 API。
- 【必须】组件文件用 PascalCase 命名：`WarehouseLayout.vue`。
- 【必须】props 用 `defineProps` 声明类型，emits 用 `defineEmits`，禁止隐式 any。
- 【必须】样式用 `<style scoped>`，避免全局样式污染；主题变量统一放 `styles/`。

### 5.2 平面图公共组件（c，C-F1，对应 COM-5）

**【必须】** 平面图由 c 提供为**唯一公共组件**，a、b 只消费、不复制。统一 props/emits 契约：

```vue
<WarehouseLayout
  :locations="locations"
  :exit="exitPoint"
  :highlight="highlightIds"
  :path="pathPoints"
  @location-click="onLocationClick"
/>
```

| props | 类型 | 提供方场景 |
| --- | --- | --- |
| `locations` | `Location[]` | a 仓库布局、b 推荐高亮、c 路径 |
| `exit` | `{ x, y }` | 出库口标记 |
| `highlight` | `number[]` | b 推荐高亮 |
| `path` | `{ x, y }[]` | c 拣选路径 |

> 组件接口变更须由 c 发起、a/b 确认（冻结契约 COM-5），禁止消费方私自改组件内部。

### 5.3 路由与权限守卫（a）

**【必须】** 路由 `meta.permission` 声明所需权限，全局守卫统一校验（前端仅做显隐，后端仍强制鉴权）：

```ts
{ path: '/admin/users', component: UserList, meta: { permission: 'user:manage' } }

router.beforeEach((to) => {
  const auth = useAuthStore()
  if (to.meta.permission && !auth.hasPermission(to.meta.permission)) {
    return { name: '403' }
  }
})
```

### 5.4 API 请求封装

**【必须】** 统一 axios 实例，集中处理鉴权头、统一响应与错误码：

```ts
const http = axios.create({ baseURL: '/api/v1' })
http.interceptors.request.use((cfg) => {
  cfg.headers.Authorization = `Bearer ${getToken()}`
  return cfg
})
http.interceptors.response.use(
  (r) => r.data,                 // 直接返回 { code, message, data }
  (err) => handleError(err)      // 401 跳登录、403 提示无权限、422 提示业务错误
)
```

- 【必须】接口定义集中在 `src/api/`，按模块分文件（`auth.ts`、`data.ts`、`recommend.ts`、`compare.ts`、`simulation.ts`），与《接口文档》编号一一对应。
- 【必须】TS 类型与后端 DTO/响应结构保持一致，字段命名一致（禁止前端私自改名）。

### 5.5 状态管理（Pinia）

- 【推荐】仅全局共享状态入 store（如当前用户/权限、仓库上下文），页面局部状态用组件内 `ref`。
- 【必须】`authStore` 缓存用户 + 权限列表，供守卫与菜单显隐使用。

### 5.6 图表规范

- 【必须】图表用 ECharts，封装统一主题与配色；禁止在页面内散写 option。
- 【推荐】大数据量（万级库位）用 Canvas 绘制平面图，避免 DOM 节点过多影响性能（NFR-1/NFR-5）。

## 10. 分工协作约定（关键）

1. **冻结契约优先**：数据库 schema（a，Flyway 脚本）、接口文档（b 牵头）、鉴权（a，Spring Security 配置）、平面图组件（c）、距离口径（c）为冻结契约，任何人不得擅自变更。
2. **变更流程**：需改冻结契约时，由**提供方**发起、相关消费方确认、更新对应文档后再改代码。
3. **跨模块引用**：c 的 `smart` 策略复用 b 的 `ScoringEngine`；b 的方案对比消费 c 的方案数据；b 的采用推荐更新 a 的库位状态——只通过公开 Service/接口调用，禁止直接改他人表逻辑。
4. **提交关联**：提交信息 `scope` 与任务编号（A-Bx/B-Bx/C-Bx）对应，便于追踪与验收。
5. **每日集成**：每天至少一次合入 `dev`，早暴露接口不一致，避免阶段七集中联调爆炸。
